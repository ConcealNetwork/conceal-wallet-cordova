Fix biometric passkey enrollment in Conceal Mobile

TL;DR

Adding a passkey in the Android app currently fails with “Biometric unlock failed” because the native plugin tries to use the secure keystore before asking for your fingerprint. We fix the order: prompt first, then store the secret. No change to camera permissions or wallet password logic.

What you'll get

  • Settings → Security → Add passkey shows the system biometric dialog and completes enrollment.
  • Unlock with fingerprint/face works after enrollment.
  • Same encrypted wallet-password storage format as the web passkey path.

How it works

The wallet still encrypts your password in JavaScript. The Cordova plugin only produces a 32-byte secret after a successful biometric check — mirroring WebAuthn PRF in browsers. Enrollment and unlock both use Android’s BiometricPrompt with a keystore-backed cipher (encrypt on enroll, decrypt on unlock). 

  Enroll:  create key → biometric prompt → encrypt secret → return to wallet
  Unlock:  biometric prompt → decrypt secret → wallet decrypts password

What changes for you

  • Rebuild APK with ./switch.sh after the plugin fix.
  • No new permissions beyond biometrics already declared.

Risks and open questions

  • Devices with only “weak” biometrics must match prompt settings (we align with availability check).
  • Must rebuild native platform; www-only export is not enough.

Out of scope

  • Camera permission flow (confirmed working).
  • Android browser WebAuthn / PRF limitations.
  • Removing legacy passkey polyfill in www.
